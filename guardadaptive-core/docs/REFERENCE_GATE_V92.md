# GuardAdaptive v0.92 | Two-stream physical-reference research gate

## Purpose

v0.92 adds a **read-only, offline Rust gate**, `src/bin/reference_gate_v92.rs`. It aligns a controller trace with a *separately captured* intended-position reference trace. The measurements are still **unverified annotations** until a calibrated independent sensor, trace origin, and integrity are confirmed.

The goal is to measure:
- normalized radial raw and output error relative to independently observed intended position
- suppression or reversal of intentional motion
- missing, duplicated, reordered or poorly synchronized samples
- phase duration and basic experimental completeness

It does **not** modify stick output, sample a HID device, upload data, or authorize production. A numeric PASS is **not** a physical certificate.

## File 1: controller measurements

UTF-8 CSV with exactly this header:

```csv
t_ms,raw_x,raw_y,output_x,output_y
```

Each row has a shared monotonic timestamp in integer milliseconds and raw + observed algorithm-output stick vectors. All values are normalized to [-1, 1]. Do not replace `output` with a simulated perfect intention and then call the result a physical test. Trace output must be generated by the frozen candidate independently of the ground-truth reference.

## File 2: independent position reference

UTF-8 CSV with exactly this header:

```csv
t_ms,phase,intent_x,intent_y
```

The `intent_x` and `intent_y` reference axes MUST represent a **calibrated independent measurement** (for example, a mechanical joystick fixture with an external shaft-position sensor) transformed into the same normalized coordinate system as the controller. Controller raw axes must **not** be copied or re-labeled as ground truth.

The `phase` is exactly one of these ordered, contiguous segments:

1. `neutral`: physically released position, measured reference vector no greater than 0.0005 radial
2. `micro`: deliberately applied 0.0001–0.015 radial displacement with independent motion reference
3. `hold`: intended displacement at least 0.01 radial
4. `reversal`: both positive and negative horizontal reference direction, absolute x at least 0.005 in every sample
5. `abrupt`: new drift condition after confirmed physical release, external reference <=0.0005 radial

At least **32 matched rows** and **500 milliseconds** of matched observations are required per phase. The gate requires contiguous monotonic clocks, no >50ms gaps, at least 95% one-to-one timestamp pairing in each stream, and **4ms or less absolute timestamp error**. Maximum file size is 8MB per file and maximum samples 50,000 per stream. These parameters describe a conservative research protocol, not physical sensor performance.

**Important:** Both files must use a common timebase established by the acquisition hardware/software. The tool does not infer an unknown clock offset or measure USB-to-display latency. Streams with different sampling rates that cannot yield 95% one-to-one pairing are deliberately rejected. Physically independent motion sensors must be synchronized and calibrated *before* conducting acceptance tests.

## Running offline

From `guardadaptive-core` in the published repository:

```powershell
cargo test --locked --offline --bin reference_gate_v92
cargo run --locked --offline --bin reference_gate_v92 -- --controller "C:\\lab\\controller.csv" --reference "C:\\lab\\reference.csv"
```

The files are read-only, processed in memory, and never uploaded. The application prints phase aggregates only. File paths are input arguments; their physical or independent origin cannot be established from them.

### Numeric research thresholds (NOT physical approval)

- `neutral`, `abrupt`: strict output error <0.009 radial (0.9%)
- `micro`, `hold`, `reversal`: strict maximum vector error <0.002 (0.2 percentage points), **zero completely erased micro movements**, **zero direction reversals**
- Report raw/output maximum and RMS errors for all five phases, matched samples, alignment error, erased and reversed samples
- The tool may report `V92_NUMERIC_RESEARCH_TARGET=PASS` on fabricated or synthetic data. It will **always** report `V92_PHYSICAL_ACCEPTANCE=BLOCKED`, `V92_PRODUCTION=BLOCKED`, `V92_GAME_OUTPUT=DISABLED`.

## Physical provenance checklist (outside the software gate)

Before interpreting results as independent physical evidence, an operator must verify the independent sensor's calibration, controller fixture and true released positions; check time synchronization uncertainties, document reference coordinates and error propagation, freeze the filter and parameter choices **before** holdout, obtain informed consent for recording and retention, and repeat on multiple truly distinct physical controllers. Do not count two sessions from the same person as two independent participants.

Data fields are intentionally numeric-only, but joystick signatures can still indirectly identify a device. Do not upload raw traces to public GitHub. Store them privately with explicit consent and a deletion policy.

## Known limitations

- **Critical:** identical raw analog input can be unseen drift or held intentional movement. Without an independent motion reference or validated release, a universally correct automatic correction is information-theoretically impossible.
- The v0.92 pairing gate cannot authenticate a CSV's external source, sensor precision, phase truth or timestamps: output is a **research metric**, not a physical approval.
- A slow drift ramp can occur without the tool detecting its origin; the five-phase trace tests only the externally identified phases.
- USB polling, user-perceived latency, operation inside games, and long-term physical micro-motion preservation remain unmeasured.
- No controller is currently detected on Naveax or work-pc, so real hardware acceptance remains pending.
